# CRDT Rules (Character Layer)

## 1. Character Identification

Each character in the document is uniquely identified using a **CharId**.

A CharId consists of:

* **userId** → the user who created the character
* **clock** → a logical timestamp assigned by that user

So each character ID is a pair:
(userId, clock)

This guarantees that every character inserted by any user is uniquely identifiable across all replicas.

## 2. Character Ordering

Characters that share the same parent must be ordered **deterministically** so all users see the same document state.

The ordering rule is:

1. Characters with a **higher clock value come first**
2. If two characters have the same clock:

   * compare their **userId lexicographically**
3. If still equal (rare case):

   * compare full CharId to ensure stability

This rule ensures that concurrent insertions at the same position are resolved consistently across all users.

## 3. Tombstones (Deletion Handling)

Characters are **not physically removed** when deleted.

Instead, each character node has a:

* **tombstone flag (boolean)**

When a character is deleted:

* its tombstone flag is set to **true**
* the character remains in the CRDT structure

### Why tombstones are needed:

* Other users may still reference that character
* Future insert operations may depend on its position
* Removing it would break consistency between replicas

### Rendering behavior:

* Tombstoned characters are **ignored** when generating visible text

## 4. Visibility Rule

A character is visible if:

* tombstone == false

A character is hidden if:

* tombstone == true

## 5. Summary

* Each character is uniquely identified by (userId, clock)
* Ordering is deterministic using clock and userId
* Deletions are handled using tombstones (no physical removal)
* Visible text is generated by skipping tombstoned characters
